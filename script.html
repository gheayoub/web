NpcAPI

Modern queued NPC API: exact name -> live UID -> interaction tile.

``search_start`` is the point where NPC discovery begins. When omitted,
NpcWorker captures the live player XYZ after the playback hold has stopped
the current movement. ``player_spot`` remains a compatibility alias only.

api.npc.open(name, search_start, search_radius, timeout, template_id, max_probe_depth, task_key, force, player_spot)

Open an exact-name NPC using a dynamic search start.

Preferred use::

npc.open("Seraphine", search_radius=7)

NpcWorker acquires the playback hold first, waits for movement to become
idle, then snapshots the current absolute XYZ as ``search_start``.
Supplying ``search_start`` is optional and explicit. The legacy
``player_spot`` keyword is accepted as an alias so older scripts keep
loading, but it no longer means a return location.

``max_probe_depth`` is accepted for source compatibility and is exposed
in status, but blind cardinal probing is no longer used.
